# Plan: Sona POC v1 (2026-10-06)

**Scope and decisions:** [`docs/architecture.md`](../architecture.md), D-002 to D-007. Its Data Model section lists the database rules each step must add.

**Branch:** `feat/poc`. One PR, opened when the work is finished.

**How we build:**

- **One sequence:** the steps are built in order, one commit (or a few) each.
- **Test-first:** red, then green.
- **Reviewed:** a fresh-context review before every commit.
- **Side tasks can run in background agents** while the main sequence continues, as long as they don't touch the same files. Examples: drafting seed content, browser smoke tests.

## Steps

1. [x] **Design.** Decisions D-002 to D-007, the data model, the glossary and this plan.
2. [x] **Generate auth.** Run `mix phx.gen.auth Accounts User users --live` (magic links) and commit the output as generated, with tests green.
3. [x] **Companies.**
   - `Company`, `Site` and `TeamMember` (with `name`), with composite company foreign keys.
   - Offboarding, which returns the expired tokens.
   - The `company` scope in config, and a pointer to D-003 in AGENTS.md's "Scope is sacred".
   - `UserAuth` adds the active team member to the scope.
   - The team gate (`live_session` + `on_mount`) and the "you're not on a team" page.
   - Fixtures.
   - Negative tests across two companies, and for a team member who has left.
   - Moved to the steps that first use them: `Audience` (step 6) and `CompanyValue` (step 9).
4. [ ] **Seeds and persona switcher.**
   - A fictional multi-site company: a head office, three sites, about 15 team members, values, channels and some history.
   - A second company for isolation.
   - `/dev/personas`, with `dev_routes` enabled in tests.
5. [ ] **App shell.** A phone-first layout with a bottom tab bar (Home, Chats) and a header showing your site and name.
6. [ ] **Chat: channels and messages.**
   - The `Audience` module: query filter and topics.
   - Visible conversations, matched by audience.
   - The conversation view and sending a message.
   - Real-time delivery over `conversation:<id>`.
   - History paginated by `id`.
   - Negative tests for conversation ids.
7. [ ] **Chat: direct conversations and unread counts.**
   - Find or create a direct conversation with a colleague.
   - The `team_member:<id>` topic carries the first message.
   - Read markers (an upsert of `last_read_message_id`).
   - Unread counts in the chats list.
   - Negative tests for colleague ids.
8. [ ] **Feed: announcements.**
   - Managers post to an audience; `Feed` checks the role itself.
   - Home shows "Needs your attention".
   - Acknowledging records who and when.
   - Real-time delivery over the audience topics.
   - Negative tests for post ids and audience ids.
9. [ ] **Feed: shout-outs.**
   - `CompanyValue`, with seeded values.
   - Recognise a colleague for a company value. The shout-out appears in everyone's feed.
   - Negative tests for recipient ids and value ids.
10. [ ] **Browser pass.** Use a phone viewport (390×844) and two browser contexts for real-time, and fix what it finds.
11. [ ] **Wrap-up.** A demo script in the README, the session log, then push and open the PR.

## Likely next requests

|---------|----------------|
| "Who hasn't read the rota change?" | `Acknowledgement` rows against the audience (the manager view) |

| "Post to the kitchen at every site" | An audience with no site and the kitchen department (D-004) |
| "Don't message me on my day off" | Shifts and quiet hours (Open Questions) |
| "Half my kitchen speaks Portuguese" | Translating messages through an LLM API (Open Questions) |
| "We need photos of the broken fridge" | LiveView uploads on messages |
